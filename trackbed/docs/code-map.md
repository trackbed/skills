# Code Map

Use this map to choose the first files to read and the closest focused test to run. After the focused check, use `make -C trackbed test-smoke` for representative feedback, `pr-verify` for Pull Request gates, or `verify` for release candidates. The full command list lives in [development.md](development.md#running-the-tests) and the [Makefile](../Makefile).

## Test Entry Points

Source paths in this map are relative to the repository root. Paths passed through Make file variables are relative to `trackbed/`.

| Scope | Complete suite | Focused file |
| --- | --- | --- |
| Node | `make -C trackbed test-node` | `make -C trackbed test-node-file NODE_TEST_FILE=tests/node/<file>.test.js` |
| Python | `make -C trackbed test-python` | `make -C trackbed test-python-file PYTHON_TEST_FILE=tests/python/test_<name>.py` |
| Bats | `make -C trackbed test-bats` | `make -C trackbed test-bats-file BATS_TEST_FILE=tests/<name>.bats` |
| Converter | `make -C trackbed test-convert` (Node converter contracts plus Bats CLI smoke) | `make -C trackbed test-node-file NODE_TEST_FILE=tests/node/converter-core.test.js` (also `converter-build.test.js`, `converter-integration.test.js`, `codex-cli.test.js`, `codex-hook-compat.test.js`, or `legacy-install-cleanup.test.js`) or `make -C trackbed test-bats-file BATS_TEST_FILE=tests/convert-plugin.bats` |

## Skill Contract Lookup

From the repository root, look up every registered suite and contract kind for an exact `SKILL.md` path:

```bash
skill_path="trackbed/skills/pr:create/SKILL.md"
jq -r --arg skill "$skill_path" \
  '.skill_contracts[] | select(.skills | index($skill)) | [.kind, .suite] | @tsv' \
  trackbed/config/coverage-production-sources.json
```

Run each returned suite through the focused Bats entry point, removing the leading `trackbed/` from the stored suite path:

```bash
make -C trackbed test-bats-file BATS_TEST_FILE=tests/pr-create-guidance.bats
```

Run a returned `tests/python/` suite through the focused Python entry point instead, for example `make -C trackbed test-python-file PYTHON_TEST_FILE=tests/python/test_issue_to_pr_preflight.py`.

The linter compares Bats and Python suite path references against this lookup. A reference to any file inside a skill directory is a coverage candidate; read the suite to confirm that it asserts on the skill before adding a mapping. Missing mappings and stale `guidance` or `executable` entries fail lint. `registry`, `evaluation`, Node suites, and paths outside skill directories are excluded from stale checks.

The static scan recognizes literal `skills/<name>` paths and Python quoted path joins. For incidental path mentions or coverage through constructed paths that the scan cannot resolve, record `{suite, skill, kind, reason}` in `skill_contract_exceptions` beside `skill_contracts` in the same JSON file. Keep real coverage mapped even when it needs an exception; incidental mentions belong only in the exception list. Use `kind: incidental` for a path mention and `kind: indirect` for a constructed file read. Indirect exceptions suppress stale-reference diagnostics but still require the mapping; incidental exceptions suppress missing-reference diagnostics. Every exception requires a non-empty reason. Broad wildcard inventory checks do not imply a per-skill mapping.

No lookup result means the skill is still listed under `skill_contract_coverage.mechanical_only` in `trackbed/scripts/synced-contracts.yaml`. The linter warns for that reviewed debt and fails when a skill is in neither the behavioral registry nor the explicit burndown.

## Common Investigation Paths

When a skill behaves incorrectly, start with its `SKILL.md`, then load only the files it references: its own skill directory and any plugin-level `trackbed/shared/` or `trackbed/scripts/` paths its `SKILL.md` names. Check `trackbed/scripts/lint-skill-contracts.py` if the issue is frontmatter, naming, description length, platform filtering, or self-contained resource policy.

When a hook blocks or misses a command, inspect the hook script, then the shared helpers under `trackbed/hooks/lib/` (see `trackbed/hooks/lib/README.md` for the helper responsibility map). `git_command_parser.py` is the executable entry point the hooks invoke; the parser for complex shell and git command shapes lives in `trackbed/hooks/lib/command_safety/`, one module per policy mode over shared syntax, vocabulary, prefix, and lexer layers.

For skill usage report and scan output, degraded-input diagnostics, and strict mode, see [hooks.md](hooks.md#skill-usage-stats).

When Codex output is wrong, read `trackbed/scripts/convert-plugin.js` first, then follow the boundary in `trackbed/scripts/convert-plugin/README.md`: loader, transformer, plugin builder, Codex CLI registration, and legacy cleanup.

When browser or visual skills cannot find an app, read `trackbed/scripts/dev-server/README.md`, the relevant shell detector, and the skill-local reference that calls it.
