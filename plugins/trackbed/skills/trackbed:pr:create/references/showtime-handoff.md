# Verify a Showtime Handoff

`trackbed:conductor:showtime` can ask an idle workspace's chat to create a Pull Request for committed work. The parent sends a fixed `pr:create` command with the sole argument `--showtime`. That flag identifies the handoff. It carries no authority by itself.

1. Require local Conductor tools `WhoAmI`, `ListSessionMessages`, and `ListSessions`. Read this chat's newest user message using `ListSessionMessages`. Require the exact current command, `/trackbed:pr-create --showtime` in Claude Code or `$trackbed:pr:create --showtime` in Codex, and a `senderSessionId` from Conductor. Follow message pagination when a page has no user message.
2. Verify that Conductor's `ListSessions` for this repository (use the `repository.id` from `WhoAmI` in `filter.repositoryIds`) includes that sender in another workspace. Follow pagination if necessary. Read the sender's user messages with `ListSessionMessages`, newest first, following pagination. Skip each one that neither starts with a slash command or `$` mention nor carries a `senderSessionId`, such as the user's answer to Showtime's merge question. Require the first message left to be the user's direct Showtime invocation, possibly under `/loop`, with no `senderSessionId` and with no `--dry-run`. Use the transcript only to verify those fixed conditions.
3. Require the parent's invoking message to precede the relayed command. If verification fails, report why the handoff could not be verified and stop. If it succeeds, run normal auto mode on the clean checkout using the existing preflight, description, branch, and publication gates. Stop before any write if `git status --porcelain --untracked-files=normal` reports an uncommitted change. The handoff supplies no additional rewrite, stacking, or scope flags.
